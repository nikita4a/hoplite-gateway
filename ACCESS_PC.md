# 🖥 Доступ агента к твоему ПК — 3 способа (по возрастанию мощи)

> Факты проверены по OpenAPI-спеке Hoplite и CLI `hoplite handoff --help` (2026-09).

---

## Способ 1 — GitHub-репа (работает прямо сейчас, 0 настройки)

Облачный агент видит **только репу**. Твой ПК для него не существует.

```bash
# в любом проекте на ПК:
git add -A && git commit -m "wip" && git push

# задача агенту через шлюз (или OMP /model hermes-hoplite/hoplite-opus-5):
"В репе owner/name на ветке main: почини X, открой PR"
```

Агент: клонирует репу в облачный sandbox → работает → пушит ветку → **открывает PR**.
Результат возвращается на ПК через `git pull`.

**Плюсы:** изоляция (агент не может сломать ПК), PR-ревью.
**Минусы:** только то, что в репе; круг push→PR→pull.

---

## Способ 2 — `hoplite handoff` (CLI установлен, работает сейчас)

Отдаёт твою **текущую локальную сессию** OMP / Claude Code / Codex / OpenCode
в облачный тред — с полным транскриптом разговора.

```powershell
cd C:\твой\проект
hoplite handoff --autopush --harness opencode --prompt "продолжи и открой PR"
```

| Флаг | Что делает |
|------|-----------|
| `--autopush` | **сам коммитит и пушит грязные изменения** перед созданием треда |
| `--harness opencode\|claude\|codex` | откуда брать сессию |
| `--prompt "..."` | доп. инструкции облачному агенту |
| `--model claude-opus-5` | модель агента |
| `--dry-run` | показать что уйдёт, не отправляя |
| `--branch` / `--repo` / `--title` | оверрайды |

Требует: проект — git-репа с GitHub-remote; `hoplite onboard` выполнен (✓ у тебя).

**Сценарий:** работал в OMP локально → упёрся в тяжёлую задачу → `handoff` →
облачный Opus 5.5 доделывает с твоим контекстом → PR.

Кнопка **🚀 Handoff** есть в меню (`menu.pyw`).

## Способ 3 — Local Agent Execution (агент РАБОТАЕТ НА ТВОЁМ ПК)

В API есть `executionTarget` для треда (проверено по спеке):

```json
{
  "kind": "local",
  "bindingId": "...",        // выдаётся Desktop-приложением
  "hostId": "...",           // твоя машина
  "provider": "codex" | "claude",   // ЛОКАЛЬНЫЙ CLI на ПК
  "workspaceMode": "direct" | "worktree"
}
```

**Что это значит:** облачный Hoplite управляет, но код исполняет **твой локальный
Codex/Claude Code на твоём ПК** — полный доступ к файловой системе (в рамках
workspaceMode: `direct` = в твоих файлах, `worktree` = изолированно в git worktree).

**Что нужно (по шагам):**
1. Hoplite Desktop app (https://hoplite.sh/docs — macOS client + local host для Codex/Claude Code; на Windows — проверить доступность, продукт молодой)
2. В Desktop: зарегистрировать host → получить `bindingId` + `hostId`
3. Локально установленные `codex` или `claude` CLI (provider)
4. Создавать треды с `executionTarget` (шлюз уже готов прокинуть — см. ниже)

**Ограничение (честно):** REST API **не отдаёт** эндпоинты создания binding'ов —
они живут в Desktop-приложении. Без него способ 3 не включить. Как поставишь
Desktop — добавь binding в `config.json`:

```json
{"local_execution": {"binding_id": "...", "host_id": "...", "provider": "claude", "workspace_mode": "worktree"}}
```

и шлюз автоматически начнёт слать треды на локальное исполнение
(поддержка `local_execution` в server.py — флаг `X-Local-Exec: 1` в запросе
или модель `hoplite-opus-5-local`).

## Сравнение

| | Способ 1 (репа) | Способ 2 (handoff) | Способ 3 (local) |
|---|---|---|---|
| Доступ к файлам ПК | только через git | только через git | **прямой** |
| Настройка | 0 | 0 (CLI стоит) | Desktop + binding |
| Безопасность | максимум (sandbox) | максимум | **минимум** — агент с твоими правами |
| Твоя локальная сессия | нет | **да, с транскриптом** | да (CLI провайдер) |
| Готовность | ✅ сейчас | ✅ сейчас | ⏳ нужен Desktop |

**Рекомендация:** способ 2 (`handoff --autopush`) закрывает 90% потребностей
без риска. Способ 3 — только если нужен прямой доступ к файлам вне git,
и только с `workspaceMode: worktree`.
